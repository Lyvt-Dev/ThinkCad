# 1.3.1 architecture and validation

## Boundaries

- `NetTopology` owns an immutable electrical connectivity snapshot. The former
  `Nodes` implementation in circuit.cpp now uses it; contact semantics did not
  change. Endpoint and wire IDs remain persisted identities, net indices do not.
  Iterative union-find avoids recursive chains. The UI caches by an electrical
  signature excluding component position, color and wire bends.
- `DiagnosticEngine` takes document, topology, solved state and actual configured
  UART/captured bus data. It returns typed issues with stable rule IDs and targets.
  `DiagnosticsPanel` localizes and filters results. Analysis runs only while the
  panel is visible, at most every 250 ms for unchanged topology. It does not parse
  sketch code or fabricate peripherals. General solver errors remain available.
- `visual::BlockProgram` is a Qt-independent typed AST. `ExpressionParser` accepts
  only a bounded expression grammar; `ArduinoCodeGenerator` validates names,
  scope, types, pins, functions and command arity before producing stable C++.
  There are no raw-statement blocks. Integer variables use int32_t on both hosts.
- `BlockPersistence` maps AST to a versioned JSON object with depth/node/size bounds.
  `BlockEditor` controls source synchronization and explicit replacement.
  `BlockScene` is presentation; structure order determines execution. Normal
  CodeInterpreter compilation handles generated sketches without a second runtime.
- `measurement::TraceStore`, `acquire`, `crossed` and `csv` are GUI-independent.
  Missing reference/voltage is not coerced to zero. Time is monotonic and samples
  at the same timestamp replace, rather than inventing zero-duration transitions.
  Existing decoders remain in measurements.cpp, with documented protocol limits.
- `BusTraffic::setConsumer` allows optional inspector, diagnostic and measurement
  acquisition without one hidden view disabling another consumer. Storage remains
  bounded. No consumers means no protocol-history retention by the application.
- `CircuitExporter`, `BomBuilder`, `ProjectExporter` and `ZipWriter` provide local
  exports. QtSvg is the only added application module. ZIP has stored entries,
  CRC32, UTF-8 paths, collision/path checks and bounded total size. QSaveFile commits
  completed exports atomically. Private library root paths are not exported.

## Project migration

Format 8 adds optional `visual` metadata at the root sketch and each board sketch.
Existing formats 1–7 retain their original code and default coding mode. Unknown
visual schemas are kept opaque and do not prevent C++ editing/execution. Metadata
includes AST, generator version, source fingerprint, view mode, visual layout and
one recoverable manual-code backup. It passes through project snapshots, recovery,
clipboard and LAN encoding. Derived topology and live trace samples are excluded.
Older application versions reject format 8 instead of misreading its metadata.

## Tests

`visual_core_tests`: code determinism, precedence, rejected statement injection,
board pins, types, scopes, descending/zero-step loops, return checks, breadboard
strips/rails, non-mutating net preview, geometry-independent signatures, shorts,
LED current, supply checks, I2C conflicts/ACK/NACK, UART role errors, proper crossed
UART wiring and isolated battery return paths.

`feature129_tests`: compile every offered command using the real sketch compiler;
project/LAN migration; manual source replacement and backup; nested branch
preservation; MicroPython editing guard; breadboard hover and undo; geometric
wire overlaps; monotonic bounded acquisition, missing voltages, trigger crossing,
CSV; PNG/SVG validation; ZIP read-back with independent Python zipfile and CRC;
behavioral execution of all twelve wired starter projects.

Existing circuit, analog, instrument, editor, debugger, collaboration and language
suites remain required. Starter behavioral tests replace redundant execution in
legacy example-data enumeration. No existing feature suite is disabled.
