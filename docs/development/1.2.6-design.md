# Implementation notes (work in progress)

Preserve normal native host sketch execution, the existing Qt Widgets editor,
Wire/I2cDevices, peripheral adapters and circuit solver. Feature additions should
be separate small modules, with necessary integration hooks. Do not claim CPU
instruction emulation. Do not enable network listeners automatically.

## Components / execution

- New appended PartKind::Module uses ModuleRegistry descriptors, preserving all
  existing serialized numeric kinds. ModulePackages imports validated data-only
  JSON from local files/directories (including checked-out local Git repositories).
- Builtin devices: BME280 I2C/SPI, MPU6050, DHT22, HC-SR04, DS18B20, WS2812B,
  L298N, MFRC522, MCP3008. Existing SSD1306 and PN532 remain.
- Register-package parameters map to bounded byte registers. Reject duplicate
  IDs, executable hooks, invalid pins/voltages/encodings and local/builtin clashes.
- Project format 4 embeds only used local descriptors, execution mode, later
  debugger metadata. Versions 1–3 continue loading in Simulation irrespective of
  the global new-project default. Mode changes are blocked while running.
- New BoardProfile catalog: ESP32-C3/S2/C6, Pico RP2040, STM32F103. Existing names
  retained. CodeInterpreter generates SDK pin/ADC/input-only masks for these
  boards instead of duplicating board validation in every SDK function.

## Next protocol work

Extend I2cDevices (already register-level OLED/LCD in v1.2.3), never replace it.
Add shared register-module state and SPISettings/transfer. BME280 calibration and
raw measurement registers should match Bosch compensation; forced measurements
and MPU6050 sleep/sample/scale registers use virtual time in Emulation. Fast mode
keeps the existing behavior. Address collisions, unwired/unpowered buses and CS
selection must be tested. Bounded traces have timestamp, master/device, bus,
clock, address, TX/RX, ACK/error and stop/repeated-start fields.

Add local sensor SDK adapters using validated physical wiring, voltage and virtual
conversion times: DHT22 checksum/minimum sample interval, DS18B20 scratchpad/CRC
and conversion interval, HC-SR04 trigger/echo duration, WS2812 reset/byte ordering
and pixel frames. L298N should drive existing DC motors from actual enable/input
states, including saturation drop. MFRC522 uses synthetic test cards; do not
claim crypto/payment-card emulation. Generic plugin register banks need no code.

UART routing: Serial1/Serial2 pins/baud/parity/stop bits, bounded receive FIFOs,
byte-ready virtual timestamps across physically connected boards; retain Serial
monitor and add bus trace. GPIO interrupts use host edge queues and SDK callbacks
at explicit API/time barriers, not instruction-level MCU interrupt timing.

## Settings / tools

Group native settings into General, Simulation & Emulation, Editor/Code,
Components/Plugins, Collaboration, Performance and Shortcuts. Every control must
have an actual persisted effect. Keep the existing classic native appearance.
Add descriptor parameter controls and an environment-input panel usable while
running; no wire or component geometry editing during execution.

Bus/pin tools use bounded buffers and timer-throttled rendering. Existing Serial
Tools and InstrumentPanel/logic analyzer stay. Add pin/net connectivity/state,
module register views and bus transactions; no fabricated trace entries.

## Source debugger

Use optional LOCAL GDB/MI for actual breakpoints, next/step/finish/continue and
variable inspection. Keep default stdio runner unchanged. Debugged workers need
a separate authenticated loopback protocol connection so GDB commands cannot
mix with Arduino RPC stdin/stdout. A small SDK socket streambuf can redirect
std::cin/std::cout only when debug endpoint/token environment variables exist.
Use existing QtNetwork in CodeInterpreter; Windows native SDK sockets link
ws2_32 only for debug sketches. GDB stays optional; normal execution works without
it. Windows may bundle MSYS2 GDB alongside the existing bundled GCC, with its
matching source/license archive. Tests must execute real GDB on Windows/Linux.

CodeEditor gutter breakpoints are per source file/board. Preserve #line original
file/line mapping through SketchProject::combinedSource/prototype insertion.
Stop the watchdog while GDB is stopped. GDB registers are host registers; show
modeled GPIO/device registers separately and label them honestly.

## LAN collaboration

Explicit Host/Join only. Qt TCP listener, generated session ticket and authentication
before project data, bounded length-prefixed JSON messages and peer count. No
account, cloud storage, external service, auto-run, remote filesystem operations,
or executable plugins. Plain LAN transport should be described clearly.

Server sequences changes with revisions. Merge independent text edits using
three-way base/current/proposed ranges; overlapping replacements must produce a
visible conflict and preserve the local draft. Avoid silent last-writer loss.
Circuit operations should use stable IDs; client-specific ID namespaces prevent
concurrent new-part collisions. Serialize wire IDs optionally for new projects.
Code updates should use QTextCursor range edits to preserve caret/undo where
possible. Suppress echo loops. Queue incoming structural updates during running
simulation and apply after stop. Saving remains local to each peer's chosen path.

Test two peers, independent and conflicting code edits, simultaneous part/wire
changes, late join, disconnect/reconnect, invalid tickets/messages, payload limits,
legacy project loading, and no listener before explicit hosting.

## Release discipline

Current base 75ba376/v1.2.3; own branch feature/thinkcad-1.2.6. No own release has
been pushed. Periodically fetch main and integrate other work minimally. Before
publishing verify no other unfinished release; then merge, test final SHA,
changelog/version/package metadata, push, require Windows + Ubuntu + Fedora +
Gentoo + AppImage success, tag and run publish-existing.yml. Verify public assets.
Then start a bounded next-feature task on a new branch from current main.
