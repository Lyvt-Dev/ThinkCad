# Peripheral implementation status (1.2.6 work in progress)

This is a development record, not a release announcement. Native sketches run on
the host CPU. The optional Emulation mode models peripheral transactions and
virtual time, not ESP32/Xtensa/ARM/RISC-V machine instructions.

| Device | Implemented path | Limits / remaining work |
| --- | --- | --- |
| BME280 | Wire and SPI; Bosch calibration/raw measurement registers; temperature, humidity, pressure inputs; genuine Adafruit library | Transaction model, not electrical waveforms; no sensor noise model |
| MPU6050 | Wire; sleep/reset, accelerometer/gyro scaling, temperature, sample divider, data-ready status, bounded FIFO; genuine Adafruit library | INT output and motion-detection engine remain to implement |
| MFRC522 | SPI registers, FIFO, CRC_A, REQA/WUPA, 4/7-byte UID anticollision/select, HALT; genuine MFRC522 library | Synthetic local test tags; no MIFARE encryption or tag memory emulation |
| MCP3008 | SPI single/differential ADC, actual channel/reference wiring | Sampling capacitance and SPI bit waveform are not modeled |
| DS18B20 | Native OneWire bridge and genuine DallasTemperature; ROM addressing/search (including bitwise alarm search), scratchpad, CRC, 9–12-bit conversions, alarm limits, configuration copy/recall; copied configuration survives supply loss | Externally powered devices; parasite power and EEPROM endurance are not modeled. Conversion polling has a 1 ms idle interval in the native bridge; device completion time remains resolution-dependent. EEPROM resets when starting/resetting a simulation |
| DHT22 | Native DHT adapter; signed temperature, humidity, packet checksum and two-second sample interval | DHT11 is explicitly unsupported; pulse waveform is not exposed yet |
| SSD1306 / character LCD | Existing raw Wire and native display adapters retained | Existing documented display limits remain |
| HC-SR04 | At least 10 µs trigger, 200 µs burst delay, round-trip echo at 343 m/s, 60 ms retrigger limit; actual GPIO/logic-analyzer edges; native `pulseIn` HIGH measurement also follows a resistor divider | Ambient sound speed, multiple-target reflections and acoustic interference are not modeled. | WS2812B | Native NeoPixel RGB adapter, actual GRB transport, physical DIN/DOUT chains, reset latch, supply/input logic validation, live pixel rendering and count-dependent strip size | RGB pixels at 800 kHz; no RGBW/WS2811. | L298N | Two enabled H bridges with TTL input thresholds, high-impedance disabled outputs, brake/reverse truth table, approximate 1 V + 0.3 Ω loss per output, existing motor transient model | No thermal model, current limiting, flyback diode or regulator emulation |

SPI uses actual bus wiring, common ground, rated supply, active chip select,
device mode and maximum clock. Multiple selected devices cause a collision.
I2C checks actual wiring, power and address collisions; Emulation also rejects a
held-low bus. Local data packages define bounded register banks; they cannot load
native code or executable hooks. Unused bundled source libraries are not compiled
into sketches.

Modeled register devices reset volatile state when supply disappears. RC522 also
stays unavailable while its physical RST pin is held low. The native RPC line
limit is 8192 bytes to accommodate a bounded NeoPixel frame; the total pending
buffer and message-rate limits remain in place.

UART defaults are defined centrally by `UartBus::defaultPins`; native begin calls
receive the resolved pins from the host. Explicit RX/TX pins are supported. A
GPIO cannot be assigned to two active UARTs on one board. ESP8266 Serial1 is
TX-only. ESP32-S2/C3/C6 expose UART0/1, ESP32/S3 and the basic STM32 profile expose
three ports, and Uno/Nano expose UART0. Receiver mismatches reject the frame;
overlapping senders invalidate pending frames. The model does not reconstruct
individual bit errors, and overlapping frames already consumed by an asynchronous
peer cannot be retroactively invalidated.

Interrupts are limited to D2/D3 on Uno/Nano; ESP8266 GPIO16 is rejected. Other
profiles validate their exposed GPIO pins. Unknown/floating input transitions do
not invent a definite edge. Detach/stop clear pending state; after stop the board
can be removed safely. Existing simulations without handlers do not acquire
interrupt polling or additional digital waveform sampling.

The register and physical bus tests cover IDs, calibration examples, read-only
registers, FIFO behavior, virtual conversion times, unsigned/signed encoding,
unwired/unpowered buses, chip-select, frequency, mode, bit order and collisions.
Native end-to-end tests compile real Arduino libraries and operate wired parts in
both execution modes. See `tests/feature126_tests.cpp` and the pure core bus tests.
