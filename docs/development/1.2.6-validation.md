## Resource and performance sample

Same Linux cloud machine, GCC 14, Qt 6.8.2, Debug builds. Baseline built from an
unmodified `git archive 75ba376`; current build includes the new tools. A fresh
local configuration was used for each idle application. Linux `/proc` sampled
only the GUI process every 100 ms for four seconds; RSS is the median of the last
second, CPU is the last three seconds. These are short headless/offscreen samples,
not a hardware-independent FPS or production memory guarantee.

| Idle GUI | 1.2.3 baseline | 1.2.6 candidate |
|---|---:|---:|
| RSS | 59,956 KiB | 64,680 KiB |
| CPU, one-core scale | 2.0% | 2.0% |

The measured increase is 4,724 KiB (about 4.6 MiB). No debugger process or LAN
session was started. Hidden inspector capture remains off, verified in GUI tests.

Reproducible core workload: build and run `performance_probe` (available with
`BUILD_TESTING=ON`). It verifies outputs while reporting timings, without brittle
machine-speed assertions:

| Workload | Debug sample |
|---|---:|
| 500 solves, 33 components / 48 wires / 16 driven LED branches | 1,020.3 ms |
| 100,000 modeled BME280 ID reads (pointer + read transactions) | 147.9 ms |
| 100,000 captured 512-byte UART writes | 114.8 ms |
| Retained entries after capture | 1,024 |
| Overwritten entries | 98,976 |
| Retained payload allocation per sampled TX vector | 128 bytes |
| Probe peak process RSS | 8,448 KiB |

The trace releases oversized input allocations when truncating retained payloads;
recording does not retain a large original vector capacity behind a small size.
LAN also bounds documents, peer queues and merge history. UI bus rendering is
throttled independently of acquisition.

## Platform preflight

Feature-branch preflight at `b8de903`:
- Fedora build/tests/RPM succeeded.
- AppImage build and execution on clean Gentoo succeeded.
- Ubuntu build and tests succeeded; Wayland video smoke failed while Mesa tried
  an unavailable Zink/Vulkan driver on the GPU-less runner. Qt 6.4 lazily probes EGL capabilities inside the
  first video conversion, which can exceed GStreamer’s render deadline. Conversion
  is now warmed before playback; CI explicitly installs Mesa software drivers and
  selects llvmpipe. The video test stays on.
- Windows build/test preflight is still running at the time of this entry.

No preflight artifact is a published release. Final main-branch artifacts,
installer provenance/tamper checks and Gentoo USE variants must pass before tag
publication. The updater's trusted main-branch provenance policy is unchanged.

Final local regression: versioned full Debug build and all 40 CTest tests passed
in 351.83 seconds. This includes the five new examples and original desktop
workflows. Subsequent platform diagnostics add file-based Windows test logs and
remove a test-only assumption about arrival order across two TCP connections.

Windows preflight finished with a successful MSVC build and legacy desktop/native
chrome tests, but the new LAN test failed and source/feature debugger suites timed
out. The LAN conflict assertion now accepts either valid arrival order; no server
merge rule is weakened. Focused Windows GDB diagnostics with preserved logs are
required to identify the remaining cause. Nothing has been released.

Post-checkpoint targeted checks also pass: updated LAN/GDB logging and smoke
(3 CTest cases), SDK Wire for ESP/AVR (2 cases), Pico/BME280 and translation catalog.
The Pico sketch now uses Arduino-Pico's `Wire.setSDA/setSCL`; SDK `Wire.begin()`
retains configured pins when a genuine library initializes the bus again.
